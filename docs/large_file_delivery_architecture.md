# Large File Delivery Architecture (R2 + Runtime Manifest)

## Purpose
This repo now uses a manifest-driven runtime contract so large browser/runtime files are not dependent on GitHub normal blobs or Git LFS object delivery.

Target model:

- GitHub: code, scripts, small manifests/config
- Vercel: frontend app/static pages
- Cloudflare R2 (public endpoint): large runtime/public assets
- Frontend runtime: reads canonical URLs from `public/data/runtime-manifest.json`

## Canonical manifest

Tracked manifest file:

- `public/data/runtime-manifest.json`

Mirror for existing runtime compatibility:

- `data/runtime-manifest.json`

Manifest contents are generated by:

- `scripts/publish-runtime-assets-r2.js`

Fields per asset:

- `key`
- `source_type`
- `path`
- `canonical_url`
- `generated_at`
- `size_bytes`
- `update_mode`
- `classification`
- `current_storage_mode`
- `public_use`
- `used_by_frontend`
- `served_live`
- `notes`

## Classification model

Classifications used in audit and manifest generation:

- `REPO_SMALL`: keep in GitHub + serve from repo path
- `R2_PUBLIC`: publish to R2 public URL and consume via manifest canonical URL
- `LFS_REFERENCE_ONLY`: keep in LFS/reference workflows only, not direct website runtime
- `INTERNAL_ONLY`: internal/audit/archive; never direct public runtime
- `REVIEW_REQUIRED`: uncertain or missing lineage/file; do not auto-publish

Audit output:

- `processed_data/audits/large_file_classification_audit.csv`

## Publish workflow

Script:

- `scripts/publish-runtime-assets-r2.js`

Dry run (recommended first):

```bash
npm run audit:large-file-delivery
```

Upload mode:

```bash
npm run publish:runtime-r2
```

Required env vars for upload mode:

- `UOGA_R2_S3_ENDPOINT` (example: `https://<account-id>.r2.cloudflarestorage.com`)
- `UOGA_R2_BUCKET` (R2 bucket name)

Optional env vars:

- `UOGA_R2_PUBLIC_BASE` (public read base, defaults to `https://json.uoga.workers.dev`)
- `UOGA_R2_PREFIX` (object key prefix, optional)
- `UOGA_AWS_PROFILE` (AWS CLI profile for R2 credentials)

Notes:

- Upload mode uses AWS CLI S3-compatible API calls for bulk-safe object uploads.
- Dry run still regenerates the audit CSV and manifest files.
- `INTERNAL_ONLY` and `REVIEW_REQUIRED` entries are not auto-published.
- `MANUAL_REVIEW_REQUIRED` update mode is explicit and not auto-claimed as continuous sync.

## Frontend/runtime integration

`config.js` now:

- loads runtime manifest candidates synchronously:
  - `./public/data/runtime-manifest.json`
  - `./data/runtime-manifest.json`
- prefers manifest canonical URLs for core large runtime groups
- preserves existing fallback chains (Cloudflare/object and local paths)

Integrated source groups include:

- Builder boundary index/composite sources
- Hunt Research core summary + observed/predictive engine groups
- Hunt Research ladder/master/reference groups

Focused promotion pass (June 1, 2026):

- Local fallback chains for known LFS-pointer runtime feeds were pruned:
  - `processed_data/draw_reality_engine_predictive_v2.csv`
  - `processed_data/hunt_master_enriched.csv`
- These now resolve to canonical R2/Cloudflare URLs only in runtime source lists.

## Build/deploy compatibility

`scripts/build-pages-dist.js` now includes:

- `data/runtime-manifest.json`
- `public/data/*`

This keeps the manifest reachable in `pages-dist` deployments while preserving old routes.

## Canonical domain policy (parity)

Primary host:

- `https://huntbuilder.uoga.org`

- `https://hunt-builder.uoga.org`

Enforcement layers:

- Edge redirect rule in `vercel.json` (host-based redirect to canonical host)
- Client safety redirect in `embed-mode.js` for alternate host requests that reach the app shell

Current risk:

- If alternate host DNS is not resolvable, parity cannot be tested end-to-end until DNS is restored.

## LFS cleanup guidance

Do not blanket-remove LFS. Use the classification audit to guide changes:

- keep truth/reference artifacts as `LFS_REFERENCE_ONLY`
- migrate public/runtime large files to `R2_PUBLIC`
- keep internal backups and QA artifacts out of public runtime paths

Flagged delivery smells:

- Any `R2_PUBLIC` runtime entry detected as `GIT_LFS_POINTER`
- Any live frontend dependency still sourced from a large Git/LFS path without canonical R2 manifest path
